A-017  Category | Value
A-018  Full name | Mixture of Experts (MoE)
A-019  First proposed | Jacobs et al., 1991 [1]
A-020  Core idea | Divide model capacity into multiple “experts” with a gating network that selects a small subset per input
A-021  Common routing | Top-k gating (typically k = 1 or 2)
A-022  Applications | Large-scale language modeling, translation, multimodal AI, reinforcement learning

A-025  ## 1. Overview
A-026  The Mixture of Experts (MoE) architecture partitions a neural network into multiple specialized sub-models (experts), coordinated by a gating function that dynamically routes each input to a small subset of experts. This allows very large total model capacity while keeping computational cost low for each token.
A-027  Mathematically:
A-028  y = Σ_{i ∈ TopK(G(x))} G_i(x) · E_i(x)
A-029  where E_i(x) is the output of expert i, and G_i(x) is the gating weight. Only k experts receive non-zero routing weights per token, yielding sparse activation and efficient scaling.
A-030  ----
A-031  ## 2. Background and Key Milestones
A-032  Year | Work / Organization | Key Contribution
A-033  1991 | Jacobs et al. [1] | Original MoE formulation for adaptive expert specialization
A-034  2017 | Shazeer et al. [2] | Introduced Sparsely-Gated MoE with load-balancing loss; large-scale feasibility
A-035  2020 | Lepikhin et al. (Google) [3] | GShard: MoE-Transformer hybrid enabling 600B-parameter multilingual model
A-036  2021 | Fedus et al. (Google) [4] | Switch Transformer: single-expert routing (top-1) → ~7× speedup
A-037  2022 | Zhou et al. (Google) [5] | Expert-Choice Routing (ST-MoE): experts select tokens, improving utilization
A-038  2022 | NLLB & Meta AI [6] | NLLB-MoE for machine translation, 54.5B total parameters
A-039  2023 | Mistral AI [7] | Mixtral 8×7B open-release (46.7B total / 12.9B active)
A-040  2025 | Alibaba Group [8] | Qwen3 MoE family, Apache 2.0 licensed
A-041  ----
A-042  ## 3. Core Methodology
A-043  Component | Description
A-044  Experts | Independent feed-forward blocks (FFNs) trained jointly
A-045  Gating network G(x) | Softmax router producing routing scores per expert
A-046  Top-k routing | Activates k experts per token (usually 1–2)
A-047  Load-balancing loss | Auxiliary term penalizing uneven expert usage (proportional to variance in expert utilization)
A-048  Expert parallelism | Experts distributed across devices → scalable sparse training
A-049  Noisy Top-k / token drop | Randomized routing variants to improve diversity
A-050  Sparsity ratio | Typically ≤ 10% of parameters active per token
A-051  ----

A-073  ## 6. Advantages
A-074  • Sparse computation: ≤ 10% of parameters active per token → major speed and memory savings
A-075  • Scalability: Extends to trillions of parameters without linear compute growth
A-076  • Expert specialization: Experts learn domain-specific skills (translation, reasoning, code)
A-077  • Empirical speedups: Switch Transformer achieved ~7× faster training versus dense models of equal quality [4]
A-078  ----
A-079  ## 6.5. Representative Benchmarks
A-080  Model | MMLU | GSM8K | Evaluation | Notes
A-081  Switch Transformer (1.6T) | 72% | 62% | 5-shot (2021) | Comparable to dense T5-XXL
A-082  Mixtral 8×7B (12.9B active) | 81% | 73% | 5-shot (2023) | Matches 70B dense models
A-083  Qwen3-235B* | 84% | 79% | (self-reported, 2025) | As reported by Alibaba [8]
A-084  * Self-reported results; independent verification pending.

A-087  ## 7. Limitations and Challenges
A-088  Challenge | Description | Common Mitigations
A-089  Load imbalance | Uneven token routing causes underutilized experts | Auxiliary load-balancing loss (Shazeer 2017)
A-090  Routing instability | Early training divergence from noisy gates | Warmup schedules, noise annealing
A-091  Communication overhead | Multi-device expert exchange | All-to-all optimized kernels
A-092  Inference latency | Dynamic routing adds delay in small batches | Expert caching, static routing fallbacks
A-093  Memory fragmentation | Sparse activation may waste device memory | Expert sharding and packing
A-094  ----
A-095  ## 8. Conceptual Intuition
A-096  MoE models operate like a committee of specialists: each expert focuses on certain patterns, and the gating network acts as a moderator deciding whose opinion matters for each input. This combines the expressivity of a very large model with the efficiency of sparse computation.
A-097  ----
A-098  ## 9. Related Architectures
A-099  Architecture | Relation to MoE
A-100  Mixture of Depths (MoD) | Sparsely activates layers rather than experts
A-101  Mixture of Attention Heads | Gates entire attention heads per token
A-102  Expert-Choice Routing [5] | Experts select tokens (capacity-based routing); see ST-MoE
A-103  Dynamic Token Routing / Router LLMs | Adaptive token-expert assignment per step
A-104  Mixture of Adapters / LoRA MoE | Parameter-efficient fine-tuning using modular experts

A-108  • Hierarchical and fine-grained routing for better load balancing (as demonstrated in Qwen3 architecture)
A-109  • Dynamic expert allocation based on context length and complexity
A-110  • Integration with Mixture-of-Depths for combined layer/expert sparsity

A-247  ## **1. Overview**
A-248  The **Mixture of Experts (MoE)** architecture partitions a neural network into multiple specialized sub-models (*experts*), coordinated by a **gating function** that dynamically routes each input to a small subset of experts. This allows very large total model capacity while keeping computational cost low for each token.
A-249  **Mathematical formulation:**
A-250  $$
A-251  y = \sum_{i \in \mathcal{T}} G(x)_i \cdot E_i(x), \quad \mathcal{T} = \text{TopK}(G(x))
A-252  $$
A-253  where $E_i(x)$ is the output of expert $i$, and $G(x)_i$ is the gating weight. Only $k$ experts receive non-zero routing weights per token, yielding **sparse activation** and efficient scaling.
